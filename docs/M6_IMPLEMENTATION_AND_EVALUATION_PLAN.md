# M6 完整 A0 运行：实现与评估协议

## 1. 目标与完成定义

M6 的目标是让一个不读取隐藏 RNG、未来牌序、未来遭遇、未来奖励或事件池内部顺序的智能体，独立完成 Ironclad、Ascension 0 的完整三幕运行。

只有同时满足以下条件，M6 才能标记完成：

1. 环境公开表示覆盖完整地图、当前 Boss、三把钥匙、药水容量、牌组、遗物、药水和所有动态合法动作；
2. 战斗、奖励、地图、商店、事件、火堆和 Boss 遗物均由同一整局智能体自主决策；
3. 任意已记录前缀可由 `seed + action prefix` 恢复到逐字段相同的公开状态；
4. 训练可多进程运行、保存完整 checkpoint，并从 checkpoint 恢复数据流、优化器和随机数状态；
5. 最终 checkpoint 在查看最终测试结果前冻结；
6. 最终测试集上至少出现一次完整 A0 胜利，且报告全部测试 seed，不删除崩溃、超时或失败运行；
7. 所有结论同时报告样本数和置信区间，不用挑选录像代替统计评估。

## 2. 信息边界

策略可以读取玩家在正常游戏界面中可获得的公开信息及其自身公开历史，包括：

- 当前生命、最大生命、金币、牌组、遗物、药水和钥匙；
- 当前手牌、公开牌堆计数、敌人状态和敌人意图；
- 当前幕、楼层、地图位置、完整可见地图和当前幕 Boss；
- 当前界面提供的候选动作、价格、公开成本、奖励类型和公开数量；
- 此前实际观察到的公开状态与已执行动作。

禁止读取或间接编码：

- 环境 seed；
- RNG 对象、指针、计数器或序列化内部状态；
- 未公开的抽牌顺序；
- 未发生的事件、遭遇、奖励、商店或 Boss 遗物；
- 精确克隆中保留的未来随机结果。

`LightspeedBackend.clone()` 只用于测试、诊断和已明确标注的战斗搜索。整局非战斗策略不得通过精确 clone 展望未来。战斗搜索只允许使用 `redeterminized_clone()`。

## 3. 智能体结构

正式 M6 智能体采用分层结构：

```text
整局循环动态动作 Actor-Critic
├─ 战斗：M5 信念搜索或其蒸馏策略价值网络
└─ 非战斗：共享循环状态的候选动作策略
   ├─ Neow 与事件
   ├─ 卡牌和普通奖励
   ├─ 地图路线
   ├─ 商店
   ├─ 火堆
   └─ Boss 遗物
```

主学习算法为带 GRU 历史状态的 PPO。网络对每个合法候选动作单独编码和打分，并用一个状态价值头估计公开历史的期望整局回报。Candidate-Q 保留为基线，不作为默认正式学习器。

## 4. 固定种子划分

所有范围均为闭区间；不同集合不得重叠。

| 用途 | seed |
|---|---:|
| 训练 | `0–999999` |
| 开发/冒烟 | `1000000–1000255` |
| 验证与模型选择 | `1100000–1102047` |
| 最终未见测试 | `2000000–2001023` |

正式训练 run seed 固定为 `17`、`29`、`43`。课程阶段只能从训练集合采样。最终测试 seed 在 checkpoint 冻结前不得用于调参、早停、奖励设计或模型选择。

## 5. 课程

课程只改变初始状态分布和最大运行范围，不改变游戏规则：

1. 战斗复习：首场战斗和 Act 1 普通战斗；
2. Act 1：从 Neow 开始，到 Act 1 Boss 结束；
3. Act 2：从训练轨迹中采样公开可恢复的 Act 2 起点；
4. Act 3：从训练轨迹中采样公开可恢复的 Act 3 起点；
5. 完整运行：只从 Neow 开始，完整三幕终局目标。

课程晋级由独立验证 seed 的 Act 通过率决定：Act 1 阶段阈值为 `25%`，Act 2 为 `5%`，Act 3 为 `1/64 = 1.5625%`；这些阈值只表示已获得足够成功前缀进入下一幕训练，而不是宣称当前幕已经解决。下一幕前缀优先取自训练 seed 中已到达更高幕的轨迹，并在恢复公开状态后用新的训练或验证选择 seed 重采样隐藏未来；不得按验证或最终结果筛选前缀。课程阶段可以使用公开楼层增量、阶段完成和势函数差分作为辅助信号；这些信号必须位于独立 wrapper，在完整运行阶段退火为零。正式评价只使用原始整局终局结果和独立报告的过程指标。

为降低纯离线模仿在学生闭环状态上的分布偏移，训练循环在每 25 次 PPO 更新的验证前执行两轮 DAgger 纠偏。旧的一轮结论来自后来因 Runic Dome 信息泄漏失去正式资格的 pilot，不再用于正式配置。清洁的 update 900 checkpoint 在此前未用于模型选择的验证 seed `1101024–1101087` 上重做逐轮对照，零轮、第一轮和第二轮的平均终止楼层分别为 `16.109375`、`15.796875` 和 `17.5`，机器可读结果位于 `experiments/m6_dagger_round_comparison_clean_u925.json`；因此正式训练固定为两轮。当前确定性学生策略负责产生非战斗轨迹，启发式教师只为学生实际访问到的公开状态提供合法动作标签；战斗仍由既定战斗策略执行且不计入 DAgger 监督。只有至少两个合法动作的状态进入监督，避免无选择状态虚高准确率并稀释梯度；卡牌奖励、事件、地图、火堆和商店的监督权重分别为 `1/1/3/2/4`。每轮使用 64 个按更新序号轮转的训练 seed、最多 1,000 步、3 个监督训练 epoch；第二轮相对第一轮偏移 `100000` 个训练 seed，以重新覆盖更新后学生实际访问的状态。基础轮转从训练区间偏移 `30000` 开始并在 `0–999999` 内取模，禁止使用验证或最终测试 seed。每轮使用的 seed 起止值、监督步数、加权监督量、损失和准确率均写入训练指标。

进入 Act 3 与完整运行阶段后，监督复习语料继续包含训练 seed 中真实到达 Act 3 的完整教师轨迹，以防止分幕训练遗忘 Act 1/2；复习轨迹只提供已访问公开状态上的动作标签，不改变完整运行的零 shaping 奖励。

完整运行阶段同时维护容量为 64 的前沿自模仿语料：只保留从 Neow 出发、至少进入 Act 2 的训练轨迹，移除导致失败的最后一步，并按“完整胜利、最深公开楼层、同楼层更短轨迹”的顺序保留最优前沿。该语料只监督轨迹中实际执行过的非战斗选择，不提供额外奖励、不改变初始状态分布，也不读取未来或隐藏信息。其作用是防止稀疏终局 PPO 在尚无完整胜利时遗忘已获得的 Act 1 构筑和路线能力。

完整运行阶段将在线探索参数与评估参数分离：在线网络继续接受 PPO、前沿自模仿和 DAgger 更新；评估网络使用衰减率 `0.998` 的参数 EMA，并在进入新课程阶段时重置。每次验证按“完整胜率优先、平均终止楼层次之”的字典序保存 `best-evaluation-checkpoint.pt`；最终冻结只接受该 EMA 评估 checkpoint，不使用在线网络或机械地选择最后一次更新。EMA 与模型选择规则均在查看最终测试 seed 前固定，最终测试只用于一次性泛化评估。

## 6. 基线

最终评估至少包含：

1. 随机合法动作；
2. 现有规则启发式；
3. 启发式非战斗策略 + M5 战斗信念搜索；
4. 不使用搜索的纯循环策略价值网络；
5. 分层循环网络 + M5 战斗信念搜索。

搜索方法同时报告固定模拟调用预算和墙钟时间。不得把搜索调用成本从比较中删除。

训练与课程诊断额外使用“循环非战斗策略 + 启发式战斗”组合，并在评估产物中标记为 `learned-heuristic`。该组合用于和训练期验证保持一致，不替代上述五个正式基线；`learned` 保留为纯循环网络基线，`learned-search` 表示正式分层搜索智能体。

## 7. 指标与统计

每种方法报告：

- 完整三幕胜率与 Wilson 95% 置信区间；
- Act 1、Act 2、Act 3 通过率；
- 平均/中位终止楼层及 bootstrap 95% 置信区间；
- 终止 HP、决策数、模拟调用数和墙钟时间；游戏分数仅在后端提供时报告，当前本地 `sts_lightspeed` 不提供该字段并明确保存为 `null`；
- 崩溃、非法动作、恢复失败、超时和截断次数；
- 三个训练 run 的均值、标准差和各自结果。

同一方法比较优先使用相同环境 seed 的配对差值。胜率之外的连续指标报告配对 bootstrap 区间。

## 8. 工程验证门槛

正式训练前必须通过：

1. 公共观察 JSON 往返后逐字段相同；
2. Lightspeed 与 CommunicationMod 在覆盖范围内的新增公开字段零差异；
3. 至少 1,000 个随机中间前缀通过重放恢复，恢复后的观察摘要完全相同；
4. 至少 10,000 个完整或截断训练 episode 无崩溃、死锁、非法动作和持续内存增长；
5. checkpoint 恢复后，固定输入序列的动作 logits、价值、GRU 状态和下一批采样 seed 逐位一致；
6. 多进程采样在相同 worker 数、run seed 和配置下可复现；
7. 最终配置、依赖、硬件、源码哈希、训练 seed 和评估 seed 写入机器可读实验清单。

## 9. 结果边界

M6 的结论只适用于 Ironclad、Ascension 0 和本地审计版 `sts_lightspeed`。任何向其他角色、Ascension、模组或真实游戏长期部署的外推都需要新的差分验证和独立评估。
